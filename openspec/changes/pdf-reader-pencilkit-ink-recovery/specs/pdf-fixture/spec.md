# Capability spec — `pdf-fixture`

## Purpose

Provide a 20-page PDF that is **project-authored**, **deterministic**,
**CC0**, and bundled with the application at build time at exactly
`InSummary/Resources/Fixtures/sample-bundle.pdf` so the PDF reader and
the PencilKit ink overlay have a stable, license-clean fixture to read
in Phase 2 — without shipping a hand-edited binary PDF in git history
and without reaching the network or any third-party source.

This capability defines the contract that every later Phase 2 test, the
`PDFReaderCoordinator`, the `PencilCanvasOverlay`, and the
`ReaderContainerView` depend on. The fixture path is canonical and must
not vary.

## ADDED Requirements

### Requirement: Canonical fixture path

The fixture SHALL be located at exactly
`InSummary/Resources/Fixtures/sample-bundle.pdf` (plural `Fixtures`,
hyphenated `sample-bundle.pdf`). Every test, build phase, PR description,
and capability spec SHALL reference this exact path. The wrong paths
`InSummary/Resources/Fixture/sample.pdf` (singular) and
`InSummary/Resources/Fixtures/sample.pdf` (no hyphen) SHALL NOT appear
in any Phase 2 artifact.

#### Scenario: Path appears in the build phase

- **WHEN** the build phase runs
- **THEN** the generator SHALL execute and write the fixture to
  `InSummary/Resources/Fixtures/sample-bundle.pdf`
- **AND** the resulting `sample-bundle.pdf` SHALL match the in-process
  generator output byte-for-byte.

#### Scenario: Bundle resource resolves

- **WHEN** the application reads the fixture at runtime
- **THEN** the read path SHALL resolve to
  `Bundle.main.url(forResource: "sample-bundle", withExtension: "pdf")`
- **AND** the read path SHALL NOT resolve to any URL outside the bundle.

### Requirement: Project-authored deterministic generator

The fixture SHALL be generated by project-owned code that lives in
`InSummaryTests/Support/PDFFixtureGenerator.swift`. The generator SHALL
use `PDFKit` to draw 20 letter-sized pages and SHALL be deterministic
across machines and across runs. No third-party asset, font, image, or
data file SHALL be imported by the generator.

#### Scenario: Deterministic regeneration

- **WHEN** the fixture generator is invoked twice on the same machine
- **THEN** the two outputs SHALL be byte-for-byte identical
- **AND** the SHA-256 hash of each output SHALL equal the canonical
  `fixtureContentHash` constant.

#### Scenario: Page count

- **WHEN** the generator output is loaded as a `PDFDocument`
- **THEN** `PDFDocument.pageCount` SHALL equal 20.

#### Scenario: Per-page rendering

- **WHEN** each page of the generated fixture is rendered to a
  `UIImage` at 72 DPI
- **THEN** the rendered image SHALL be non-empty (not a blank canvas)
- **AND** the rendered image SHALL embed the page index in a position
  visible to a human reviewer.

### Requirement: Fixture licensing and authorship

The fixture SHALL be released under the **CC0 1.0 Universal**
dedication. The fixture SHALL contain **no third-party content** of any
kind; every drawing primitive SHALL originate from the project's own
generator code. The generator source SHALL carry a top-of-file `// SPDX-License-Identifier: CC0-1.0`
comment asserting project authorship.

#### Scenario: License attestation

- **WHEN** a reviewer reads the generator source
- **THEN** the first non-doc comment SHALL state "CC0 1.0 Universal,
  project-authored"
- **AND** the generator SHALL NOT import any third-party asset, font,
  image, or data file.

### Requirement: License record in repo

The repository SHALL contain `InSummary/Resources/Fixtures/SAMPLE-BUNDLE-LICENSE.md`
with the CC0 1.0 Universal dedication, the generator SHA-256, and the
page count. The license file SHALL ship with the binary in *Copy Bundle
Resources*.

#### Scenario: License file is committed

- **WHEN** a reviewer inspects the fixture directory
- **THEN** `SAMPLE-BUNDLE-LICENSE.md` SHALL exist alongside
  `sample-bundle.pdf`
- **AND** the file SHALL name the CC0 1.0 Universal dedication.

### Requirement: Drift detection

The fixture's canonical content hash SHALL be checked against the
generator's output at every test run. A hash mismatch SHALL fail the
build, because the hash mismatch indicates that the bundled artifact
and the generator have drifted apart.

#### Scenario: Drift trips the suite

- **WHEN** the bundled fixture's content hash differs from the
  generator's output hash
- **THEN** the dedicated XCTest SHALL fail with a message naming both
  hashes and instructing the developer to re-run the build phase.

### Requirement: Local-only access

The fixture SHALL be loaded only from the bundle or from the in-process
generator at test time; the application SHALL NOT reach for the fixture
over the network, the file system outside the bundle, or any remote
storage.

#### Scenario: No network reach-out

- **WHEN** the fixture is loaded
- **THEN** no URL session, no socket, and no remote URL SHALL be opened
- **AND** a code search for `URLSession`, `NWConnection`, and
  `NSURLConnection` inside the fixture's loading code SHALL return
  zero matches.

## MODIFIED Requirements

*None.* This capability introduces a new fixture and a new generator
support file. It does not modify any existing Phase 1 entity.

## REMOVED Requirements

*None.*
